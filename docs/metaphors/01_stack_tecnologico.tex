\chapter{Metáfora Arquitectural del Sistema}

\section{Concepto de la Metáfora: La Torre de Control de Red y el Centinela}
En las metodologías ágiles de ingeniería de software (como eXtreme Programming y Scrum), la \textit{metáfora del sistema} es una visión compartida de alto nivel que permite a todos los desarrolladores, evaluadores y usuarios comprender intuitivamente cómo opera el software, sus componentes y su flujo de datos sin perderse en detalles de bajo nivel.

Para el presente proyecto, la metáfora rectora seleccionada es:
\begin{center}
  \textbf{\large ``La Torre de Control de Tráfico Aéreo y el Escuadrón Centinela''}
\end{center}

Bajo esta analogía operativa:
\begin{itemize}
  \item \textbf{La Torre de Control (Frontend React):} Es la cabina panorámica donde los controladores (Administradores y Operadores de red) supervisan en tiempo real la posición, altura y estado de cada aeronave mediante pantallas gráficas intuitivas, radares de topología y un panel de alertas. La torre no sale a volar ni interroga directamente a los aviones en el aire; simplemente consume la telemetría depurada que recibe del centro de radar.
  \item \textbf{El Centro de Operaciones y Despacho (Backend Node.js / Express API):} Es la central de procesamiento que aplica las reglas de seguridad, valida autorizaciones de despegue y aterrizaje, procesa las peticiones de los controladores y expone interfaces estandarizadas (API REST) para entregar datos consolidados sin sobrecargar los sistemas de vuelo.
  \item \textbf{El Escuadrón Centinela de Radar (Daemon de Monitoreo en Segundo Plano):} Es un servicio autónomo que patrulla incansablemente el espacio aéreo (la red de área local). Emite pulsos periódicos de radar (pings ICMP y barridos ARP/Nmap) para descubrir nuevas naves en el perímetro y verificar que los aviones autorizados sigan respondiendo. Si una nave no responde tras tres pulsos sucesivos, el radar no asume que se desintegró físicamente, sino que emite una notificación de emergencia a la torre.
  \item \textbf{La Bitácora de Vuelo y Caja Negra (Base de Datos MongoDB):} Es el registro inalterable donde se almacenan las coordenadas de cada aeronave, los planes de vuelo históricos, los eventos de aproximación y las incidencias detectadas para auditoría posterior y análisis estadístico a largo plazo.
\end{itemize}

Esta metáfora resuelve de forma natural la separación de responsabilidades exigida en el requerimiento RNF-03: \textit{el radar centinela continúa vigilando el espacio aéreo incluso cuando los operadores de la torre de control cierran sus ventanas de visualización}.

El sistema implementa una arquitectura modular de tres niveles desacoplados más un servicio de fondo nativo en el sistema operativo del servidor, alineándose con las directrices de la norma ISO/IEC 25010 en cuanto a modularidad, mantenibilidad y eficiencia del desempeño.

\section{Capa de Presentación: Frontend Web}
La interfaz gráfica de usuario está orientada a la operación intuitiva en salas de control y centros de soporte de laboratorio (NOC). Debe responder fluidamente en pantallas de escritorio con resolución igual o superior a $1366 \times 768$ píxeles (RNF-10).

\begin{itemize}
  \item \textbf{Librería Base:} \textbf{React 18.2+}. Permite la reactividad instantánea del estado mediante su modelo de Virtual DOM concurrente, facilitando actualizaciones selectivas del panel de control sin provocar parpadeos ni recargas completas de la página web.
  \item \textbf{Herramienta de Construcción y Empaquetado:} \textbf{Vite 5.x}. Se selecciona Vite en reemplazo del obsoleto Create React App (CRA). Vite utiliza \textit{esbuild} basado en Go para proporcionar un arranque en desarrollo prácticamente instantáneo y empaqueta el código de producción con \textit{Rollup}, reduciendo drásticamente el tamaño del bundle Javascript descargado por el navegador.
  \item \textbf{Enrutamiento del Cliente:} \textbf{React Router DOM v6}. Permite la navegación desacoplada mediante rutas protegidas por rol (\texttt{ProtectedRoute}), redirigiendo a los operadores lejos de las vistas exclusivas de administración sin requerir solicitudes adicionales de páginas HTML al servidor.
  \item \textbf{Renderizado del Grafo de Topología:} \textbf{React Flow (xyflow)}. Librería especializada en diagramación de grafos dinámicos e interactivos en React. Permite representar nodos con íconos personalizados de hardware (switches, routers, terminales), dibujar aristas con enlaces continuos (confirmados físicamente) o discontinuos (inferidos lógicamente), soportando controles de zoom, arrastre y selección rápida para inspección de fichas.
  \item \textbf{Estilizado y Sistema de Diseño:} \textbf{Tailwind CSS v3.4}. Framework utilitario que garantiza consistencia visual absoluta, cumplimiento riguroso de la paleta de colores del proyecto sin colisiones de nombres de clase, y fácil implementación de diseño responsivo adaptado a las pantallas de los laboratorios.
  \item \textbf{Iconografía Profesional:} \textbf{Lucide React}. Set moderno, limpio y vectorial de íconos que garantizan que el estado de cada nodo no se transmita únicamente mediante color, sino acompañado de símbolos inequívocos de comprobación, advertencia y fallo (RNF-11).
  \item \textbf{Cliente de Comunicación HTTP y Caché:} \textbf{Axios y TanStack Query (React Query)}. Gestiona el sondeo periódico (\textit{polling}) del panel cada 5 segundos de forma controlada, evitando fugas de memoria, manejando cancelaciones automáticas ante desmontaje de componentes e interceptando respuestas HTTP 401 para la renovación transparente de tokens.
\end{itemize}

\section{Capa de Servicios y Lógica de Negocio: Backend API REST}
El servidor de aplicaciones procesa las transacciones, gestiona la seguridad de acceso y sirve como pasarela formal entre la interfaz de usuario y la persistencia de datos.

\begin{itemize}
  \item \textbf{Entorno de Ejecución:} \textbf{Node.js v20 LTS (Iron)}. Plataforma basada en el motor V8 de Google que maneja la concurrencia mediante un bucle de eventos asíncrono no bloqueante (\textit{Event Loop}). Resulta idóneo para aplicaciones orientadas a E/S intensiva de red, donde múltiples peticiones de consulta coexisten con escrituras concurrentes de monitoreo.
  \item \textbf{Framework de Enrutamiento:} \textbf{Express.js v4.19+}. Microframework ligero y minimalista que ofrece una capa robusta de middlewares para la autenticación, control de accesos basados en roles (RBAC), registro de peticiones (\textit{Morgan}) y manejo centralizado de excepciones.
  \item \textbf{Seguridad Criptográfica de Credenciales:} \textbf{bcrypt (12 rondas de salting)}. Algoritmo de hash adaptativo que protege las contraseñas contra ataques de fuerza bruta y tablas arcoíris. No se almacenan contraseñas en texto plano bajo ninguna circunstancia (RNF-05).
  \item \textbf{Gestión de Sesiones Seguras:} \textbf{jsonwebtoken (JWT)}. Arquitectura dual de autenticación:
  \begin{itemize}
    \item \textit{Access Token:} JWT de corta vigencia (15 minutos), firmado con HMAC-SHA256, transportado en la cabecera HTTP \texttt{Authorization: Bearer}.
    \item \textit{Refresh Token:} Credencial de larga duración (8 horas), persistida en base de datos y entregada al cliente exclusivamente mediante una cookie con banderas \texttt{HttpOnly}, \texttt{Secure} y \texttt{SameSite=Lax}, mitigando de raíz ataques XSS y CSRF (Sección 8.3 de la especificación).
  \end{itemize}
  \item \textbf{Validación de Datos de Entrada:} \textbf{Zod / Joi}. Validación rigurosa de esquemas en servidor. Impide la inyección de tipos arbitrarios y garantiza que los parámetros de configuración (umbrales, timeouts, intervalos) se mantengan estrictamente dentro de los límites seguros (\textit{guardrails}) definidos en la especificación RF-10.
\end{itemize}

\section{Capa de Monitoreo y Exploración de Red: Daemon Centinela}
El proceso de monitoreo opera de forma totalmente independiente del servidor web y de las sesiones activas en el navegador (RNF-03).

\begin{itemize}
  \item \textbf{Arquitectura del Proceso:} Servicio nativo en segundo plano orquestado mediante \textbf{Systemd} en el servidor Debian del laboratorio. Si el proceso sufriera una falla inesperada, Systemd lo reinicia automáticamente en menos de 5 segundos con política \texttt{Restart=always}.
  \item \textbf{Mecanismos de Descubrimiento de Red (Capa 2 y Capa 3):}
  \begin{itemize}
    \item \textbf{arp-scan:} Herramienta nativa de Linux que envía tramas ARP a nivel de Capa de Enlace (Ethernet). Permite mapear instantáneamente todos los dispositivos activos en el segmento local del laboratorio, obteniendo su dirección IP y su dirección MAC física real de hardware, incluso si el dispositivo tiene activado un firewall personal que bloquea paquetes ICMP.
    \item \textbf{Nmap (Network Mapper):} Empleado para barridos de subred configurados (\texttt{nmap -sn}) y para resolución pasiva de fabricantes mediante consultas a la base de datos de identificadores OUI del IEEE.
  \end{itemize}
  \item \textbf{Mecanismos de Comprobación de Disponibilidad:}
  \begin{itemize}
    \item \textbf{Pings ICMP de baja sobrecarga:} Ejecución de comprobaciones de eco con tiempo de espera configurable (predeterminado 3 segundos, timeout estricto de 1 paquete).
    \item \textbf{Sondeo de puertos TCP (Layer 4 fallback):} Comprobación de sockets TCP a puertos estándar (ej. 80, 443, 22) para servidores que no responden a eco ICMP pero prestan servicios de red activos.
  \end{itemize}
  \item \textbf{Control de Concurrencia y Consumo de Recursos (RNF-15):} Limitación estricta de concurrencia mediante un pool de trabajadores asíncronos (\texttt{p-limit}) configurado a un máximo de 15 comprobaciones simultáneas. Esto impide la saturación de sockets de red y el agotamiento de descriptores de archivos en el núcleo de Linux.
\end{itemize}

\section{Capa de Persistencia: Base de Datos NoSQL}
La capa de datos utiliza un motor flexible para acomodar la naturaleza heterogénea de los equipos de red (hosts con IP, switches no administrables sin IP, puntos de acceso con múltiples clientes).

\begin{itemize}
  \item \textbf{Motor de Base de Datos:} \textbf{MongoDB 7.0 Community Edition}. Sistema de base de datos documental orientado a JSON/BSON. Permite almacenar atributos dinámicos por tipo de hardware sin requerir complejas migraciones de esquema relacional.
  \item \textbf{Mapeador Objeto-Documento (ODM):} \textbf{Mongoose v8}. Facilita la declaración de esquemas estrictos, validación de tipos a nivel de aplicación, definición de hooks (\textit{pre-save} y \textit{post-save}) para auditoría y tipado consistente.
  \item \textbf{Índices TTL (Time-To-Live) para Gestión de Capacidad:} Mecanismo automático nativo de MongoDB para depurar datos de alta frecuencia y prevenir el desbordamiento de disco en el servidor Debian (Sección 8.4 de la especificación):
  \begin{itemize}
    \item Colección \texttt{checks}: Expira automáticamente a los 30 días.
    \item Colección \texttt{events}: Expira automáticamente a los 90 días (semestre académico).
    \item Colección \texttt{sessions}: Expira automáticamente a las 24 horas tras caducar el token.
  \end{itemize}
  \item \textbf{Módulo de Agregación para Big Data:} Consultas analíticas diarias mediante el \textit{Aggregation Pipeline} de MongoDB para computar estadísticas consolidadas de disponibilidad (RF-11), resumiendo miles de pings en un único registro diario por dispositivo.
\end{itemize}

\section{Capa de Infraestructura, Red y Despliegue en Laboratorio}
\begin{itemize}
  \item \textbf{Sistema Operativo del Servidor:} \textbf{Debian GNU/Linux 12 (Bookworm) x86\_64}. Reconocido por su estabilidad inquebrantable, bajo consumo de memoria RAM y paquetes de red nativos maduros.
  \item \textbf{Servidor Web y Proxy Inverso:} \textbf{Nginx 1.22+}. Actúa como puerta de enlace frontal en el puerto 80/443 del servidor. Entrega los archivos estáticos optimizados del frontend React y redirige las rutas \texttt{/api/*} hacia el backend de Node.js en \texttt{localhost:5000}. Aísla completamente la base de datos MongoDB en el puerto local \texttt{127.0.0.1:27017}, impidiendo cualquier acceso directo desde el exterior.
  \item \textbf{Acceso Remoto Seguro (Fase 2):} \textbf{WireGuard VPN}. Protocolo de red privada virtual criptográfica de última generación que opera en el espacio de kernel de Linux. Permite a los docentes y evaluadores acceder al panel de control desde fuera del laboratorio a través de un túnel cifrado ChaCha20-Poly1305, sin exponer puertos del sistema a Internet ni comprometer la seguridad institucional.
\end{itemize}
